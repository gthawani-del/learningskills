# Director Studio — five-foundation execution audit

19 November 2026. GitHub main independently verified at `71cdcc558c30a5d8597da367c4632742942aba6a`. This is an audit and reconciliation of the approved design, not a replacement specification or new product direction. Application code, configuration, production data and provider activation were not modified. No tests, models, rendering, migrations or deployment were run for this audit. Earlier test counts are historical recorded evidence, not fresh creative acceptance.

## Verdict

The five foundations were already captured in the approved design. They have **not** all been carried through to executable, end-to-end Music Video production. The central gap is incomplete integration and execution, not lack of a foundation document. The last registry fix repaired an actual defect; it did not complete model intelligence, orchestration, evaluations, operations or finished-video delivery.

Source: [approved five-foundation design](/workspace/learningskills-director/docs/superpowers/specs/2026-11-18-music-video-director-design.md:16). The user's clarification in this audit confirms these exact five foundations. They are not five machine-learning algorithms; the earlier request for their names is resolved. No substitute taxonomy is introduced.

## Material findings

1. **Creative intent is not threaded through the normal planning route.** `routePlanning` accepts intent and evaluates measured task quality, but `createPlanningController.context` calls it without intent. Consequently the normal summary/consent/start/recovery path does not invoke this feature from approved creative preferences; default registry priority applies after admission. The separately exposed media-routing API can accept intent, so it would also be inaccurate to say intent-aware routing never exists. Required repair: bind explicit approved intent to an immutable policy/source snapshot across estimate, consent, request and recovery; preserve exact authorized model and quality floors. Evidence: [planning controller](/workspace/learningskills-director/apps/director/planning.mjs:9), [selection call](/workspace/learningskills-director/apps/director/planning.mjs:16), [ranking](/workspace/learningskills-director/apps/director/planning-router.mjs:46), [quality evaluator](/workspace/learningskills-director/apps/director/routing-intent.mjs:30).

2. **The two participation styles currently exceed what their orchestration delivers.** Their state, conversation, source-bound proposals and scoped screenplay/department handoffs exist. The mode changes instruction/copy; there is no demonstrated complete recommended production covering all remaining assets, motion, budget-to-finish, review and delivery. Required repair: compose the existing plan/treatment/department/asset/quote/job services into the same bounded production run, with one understandable production recommendation and consequential approval points. Evidence: [existing modes](/workspace/learningskills-director/apps/director/public/director-ui.js:4), [Director context and instruction](/workspace/learningskills-director/apps/director/director-context.mjs:14), [action allowlist/handlers](/workspace/learningskills-director/apps/director/director-actions.mjs:42), [approved Plan it for me experience](/workspace/learningskills-director/docs/superpowers/specs/2026-11-18-music-video-director-design.md:38).

3. **Additional router algorithms were explicitly deferred, not blocked by credentials alone.** Weighted-quality scoring, capability gates and some budget/deadline constraints are implemented. Combined quality/cost/latency utility, adaptive outcome scoring, live vendor-health aggregation and face-aware splitting were not implemented by the latest repair. Missing outcome data prevents credible calibration and activation, but does not prevent writing event contracts, deterministic aggregators, offline replay, health policies, controls and their integration. Coding such modules must not be represented as paid live qualification or permission to experiment on customers. Evidence: [existing evaluator](/workspace/learningskills-director/apps/director/routing-intent.mjs:42), [planning cost bound](/workspace/learningskills-director/apps/director/planning-router.mjs:38), [recorded deferrals](/workspace/learningskills-director/docs/MODEL_ROUTER_INTELLIGENCE_BIBLE.md:19), [latest scope evidence](/workspace/learningskills-director/docs/evidence/DIRECTOR_REGISTRY_REPAIR_2026-11-19.json:26). Scoped runtime searches are retained in `/tmp/director-learning-audit/search-evidence.json`; a zero keyword match alone is not universal proof of absence.

4. **Evidence admission is not a creative evaluation system.** Registry publication validates supplied execution/quality evidence and static task profiles. That is necessary, but does not itself execute a singing/continuity benchmark, associate actual take defects with used footage, or calculate verified complete-project acceptance/cost metrics. The latest tests expressly use synthetic model evidence. Required repair: reuse actual job/take/edit/approval IDs for explicit outcome events, artifact-backed evaluations, acceptance/defect history and reviewed policy releases. Evidence: [registry admission](/workspace/learningskills-director/apps/director/model-registry.mjs:58), [recorded synthetic limits](/workspace/learningskills-director/docs/evidence/DIRECTOR_REGISTRY_REPAIR_2026-11-19.json:15), [quality/backoffice requirements](/workspace/learningskills-director/docs/ADMIN_BACKOFFICE_BLUEPRINT.md:122), [existing benchmark/defect gaps](/workspace/learningskills-director/docs/DEVELOPMENT_TRACKER.md:410).

5. **Important production endpoints remain unavailable or incomplete.** Generic lip-sync quoting deliberately rejects unsupported execution. Hosted `/export` deliberately rejects sound-preserving export outside the gated local/demo path. These are honest guards, not completed features. Required repair: qualify and connect exact-audio singing/performance/B-roll generation and its result/selection/repair path; finish the full-song editor and durable hosted render/download using existing foundations. Evidence: [lip-sync hold](/workspace/learningskills-director/apps/director/quote-input.mjs:17), [hosted export hold](/workspace/learningskills-director/apps/director/api.mjs:340), [all eighteen deliverables](/workspace/learningskills-director/docs/MUSIC_VIDEO_RELEASE_IMPLEMENTATION.md:7). Existing low-level video/audio adapters are preserved; no claim that all media-generation code is absent is made.

6. **Backoffice is a set of operational slices, not the complete approved product.** Roles, audited global pause/model disable, reviewed registry publication and spending records exist. The actual permission/command set does not establish complete skill publication, benchmark/defect operations, support, credits/refunds, billing-feed settlement, retention/deletion or founder reporting. Required repair: close each through existing records and APIs; require explicit authority for actual money movement or irreversible production actions. Evidence: [roles/actions](/workspace/learningskills-director/apps/director/operations.mjs:3), [cost-event ingestion boundary](/workspace/learningskills-director/apps/director/cost-reconciliation.mjs:3), [commercial scope](/workspace/learningskills-director/docs/DEVELOPMENT_TRACKER.md:198), [approved backoffice blueprint](/workspace/learningskills-director/docs/ADMIN_BACKOFFICE_BLUEPRINT.md:98).

7. **The tracker contains stale, contradictory details.** Historical F002/F003 still say signup/recovery code is missing, while the current API/account-recovery implementation exists. The older consolidated audio row says automatic song analysis/transcription/alignment are missing, whereas the later song-provider adapters and review paths exist but lack live qualification. Required repair: reconcile rows using code and dated evidence; do not upgrade unqualified behavior to production accepted, and do not erase implemented work by repeating stale summaries. Evidence: [old rows](/workspace/learningskills-director/docs/DEVELOPMENT_TRACKER.md:324), [signup code](/workspace/learningskills-director/apps/director/api.mjs:106), [song runtime](/workspace/learningskills-director/apps/director/song-provider-controller.mjs:16), [older audio summary](/workspace/learningskills-director/docs/DEVELOPMENT_TRACKER.md:195).

## Required execution sequence, retaining the complete scope

1. **Reconcile authoritative status and wire intent end to end.** Correct stale tracker rows against code; pass approved routing intent through the existing production/planning path with policy versioning and authorization/currentness preservation. Code work is not blocked by live credentials.
2. **Complete bounded Director orchestration and plan composition.** Reuse treatment/department/asset/cost/job services for both participation styles. “Plan it for me” must return the complete actionable recommendation, not just a different prompt. Connect persona decisions to actual permitted actions.
3. **Complete router utility, outcome/evaluation and operational integration.** Full comparable cost/latency scoring with quality floors; actual outcome hooks, offline evaluation/replay, accepted-output economics and health/defect tools. Build dormant/preview controls where activation is not authorized; no hidden paid canaries or automatic promotions.
4. **Close motion/performance and scoped-repair workflow.** Exact-audio singing proofs, dance/camera/narrative/B-roll requests, exact approved reference bindings, results, selection, defect diagnosis and one scoped correction using existing jobs/attempt limits. Reuse assets before spending; preserve accepted neighbors.
5. **Complete full-song edit, deterministic finishing and hosted delivery.** Pin selected take/ranges to original-master timing; render captions/titles from canonical text; durable render/store/download/recovery through current architecture. No short-demo substitution.
6. **Complete the backoffice release requirements alongside these modules.** Actual benchmark/defect operations, skill/registry lifecycle, job triage, financial reconciliation/support/retention and honest founder reporting. Link each to its existing requirement ID rather than declaring the backoffice complete because a pause button exists.
7. **Run authorized real production acceptance.** Actual song/provider outputs, account isolation, full-song viewing/listening, real costs, recovery and physical devices. Distinguish technical checks, creative evaluation and user acceptance. Preserve the two-attempt target as measured, not promised.

The sequence follows the existing five-foundation design and eighteen-deliverable release dependencies, not a simplified MVP or a new infrastructure proposal. All work remains Music Video first while preserving shared multi-format modules.

## What genuinely requires an external dependency

Specific production migrations; actual hosted billable processing; paid inference/benchmark runs; access needed for real account and billing-feed checks; rights to copy covered third-party expression; real device and human creative acceptance. These gates do **not** justify withholding independent implementation, pure evaluation/aggregation code, UI wiring, dormant controls or offline recovery tests. No broad permission request is needed merely to write the already authorized code.
