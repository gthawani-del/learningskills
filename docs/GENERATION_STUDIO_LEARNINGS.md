## Consolidated lessons and application

| Lesson | Application in Director Studio | Limitation |
|---|---|---|
| Separate creative reasoning from execution guarantees | A Director can invoke the existing 17 department contracts as skills; existing deterministic permissions, costs, versions and media operations remain authoritative | An orchestration workflow is not automatically an autonomous agent; agent execution remains separate unfinished work |
| Persistent sessions need addressable assets | Refer to owned project assets, exact versions, treatment scenes and shot IDs; preserve approvals across contextual revisions | Chat memory alone cannot establish current approval or ownership |
| Discover current model capabilities and costs | Reuse the existing registry/router; separately verify schema, task fitness, price and real output | Catalogue presence or a successful request is not qualification |
| Inputs should adapt the available operation | Reuse attachment roles, model capabilities and reference selection rather than duplicate upload or generation systems | Do not silently change the user's selected model or requested output |
| Review proposals before expensive media | Reuse treatment, department-package, cast/look and storyboard approvals | Do not force 17 separate customer approval steps; planning approval is not spending or rights approval |
| Preserve exact creative/timing handoffs | Carry approved song ranges, scene boundaries, roles and source versions into shot assignments | Do not replace approved cuts with equal-spacing guesses or fabricate beat/lyric precision |
| Reuse assets before regeneration | Use existing project library, identity/look/location references and reusable media | Uploaded-person consent, licences and exact source availability still require their actual evidence |
| Generation must be nonblocking and recoverable | Reuse durable job IDs, polling, reservations and existing recovery; reload resumes the same request | Browser-local pending jobs alone are insufficient durability and must not cause duplicate paid submissions |
| Costs belong beside production decisions | Reuse preflight estimates, authorization, pending exposure and actual-charge reconciliation | Free source code does not mean free inference; include repairs, finishing and render costs |
| Camera controls express intent | Compile framing, lens, focus, movement and motivated lighting into appropriate supported inputs | Prompt modifiers do not establish calibrated optical simulation or native camera control |
| Lip-sync is a task requiring proof | Qualify singing with exact original-audio excerpts and full-motion listening/viewing; preserve singer identity and musical timing | Portrait talking-head success does not prove singing, multiple singers or a complete-song performance |
| Prompt critique is useful but insufficient | Use realism/continuity guidance and concrete failure criteria; evaluate resulting media separately | A 'plan and critique' instruction is not an output quality evaluation |
| Reusable skills need executable contracts | Inputs, tool permissions, dependencies, outputs, acceptance checks and scoped repair policy belong to every department skill | Filmmaking prose alone does not implement execution |

## Findings that must not be copied blindly

1. The reviewed fork contains React/Next and vanilla-JavaScript/Vite app paths. Documentation, model lists and implemented clients differ. Avoid parallel implementations in our application.
2. The inspected direct lip-sync clients choose OmniHuman 1.5 for portraits and a Volcengine route for video regardless of the selected model. Our router must preserve the exact selected and qualified endpoint/configuration.
3. Browser localStorage holds an API key in the standalone shell. Keep Director's existing provider keys server-side; do not copy this credential pattern.
4. The README's local-data/privacy claims do not remove external media uploads. Present actual transfer requirements and preserve private owned storage controls.
5. The README says MIT, but no licence file was present and GitHub detected no licence for the inspected fork. Resolve provenance/licensing before copying its code. These changes reuse Director code and research ideas only.
6. Hosted agent documentation does not prove the reviewed repository contains its backend. Hermes documentation describes provider compatibility, not evidence that the studio runs on Hermes.
7. Advertised model counts and lower-cost claims are not benchmarks. Compare task-matched usable output and complete delivered cost, including repairs and rejected takes.

## Music-video execution priorities

Continue the existing 18 deliverables. Complete the treatment-to-shot timing handoff, approved references, real storyboard frames/full-song animatics, singing proof, performance/narrative/dance/B-roll production, targeted repairs, editing and synchronized original-master export. Cloud activation and real-provider acceptance remain distinct gates.

Use the frozen screens and shared controls. Add no new provider, duplicate agent framework, registry, editor, approval engine or QA infrastructure. Do not claim a two-attempt quality target until representative finished projects demonstrate it.
