## First timed storyboard increment

The Storyboard stage now has a compact silent timing preview. It consumes the exact currently selected and approved private PNG for every shot, in the approved sequence order. Play/pause, scrubbing, integer frame counts and one-shot-at-a-time timing edits work without provider calls. Suggested durations come from shot contracts; explicit preparation records them as estimates. A manually saved timing version is a declared human timing choice, not measured song or dialogue alignment. Shot labels use readable titles.

Drafts reuse existing versioned `edit` production records and their owned asset references. Server-side `GET/POST /api/projects/:id/animatic` compiles/validates current pins; clients cannot submit asset URLs, arbitrary frame identities, approvals or spending authority. Saves use existing owner/version-checked persistence. No new data tables, native grants or provider routes are introduced. Earlier timing versions, storyboard specifications, selections and footage records remain intact.

The exact sequence version and every frame selection/specification/asset version are checked again on reload and playback. Missing/revoked approvals, changed frames or reordered sequences hold stale drafts. An explicit refresh creates a new timing version from current reviewed inputs. Generic edit content is treated as untrusted and cannot authorize production. A separate animatic approval/final-motion gate has not been implemented in this increment.

One aspect is required across the preview; no silent crop is applied. The existing edit-record bounds apply: at most 100 distinct referenced assets and bounded JSON content. Oversized plans fail explicitly. Timing permits 24/25/30 fps, positive integer counts, up to 900 seconds per shot and one hour total. The UI edits the saved frame rate and one shot's count at a time. A screenshot or still preview does not establish action completion or performance quality.

Playback uses the browser clock and actual private image decoding. It pauses while the next image loads and when the page becomes hidden. It is a browser preview, not an encoded frame-accurate film. Periodic source checks and checking before Play stop reuse when current evidence changes. Load failures preserve the saved draft and never request replacement generation. Unsaved timing blocks navigation/financial dialogs and remains editable after a failed save.
