## User-visible behavior

The Storyboard stage shows compact ordered rows, initially collapsed. Free preparation uses the current approved brief, screenplay and all 17 current approved department plans. It creates a clearly labelled starting coverage plan; richer cinematic coverage can be edited directly or proposed through a separately authorized AI operation. A single focused, prefilled field editor avoids an empty questionnaire.

Each contract records its source scene, character associations and exact dialogue IDs; purpose/action; estimated duration; framing, camera and lighting intent; intended start/end states and continuity; mandatory/flexible requirements with acceptance evidence and failure conditions; reference roles; control limitations; and audio/performance requirements. The screenplay remains the authority for spoken words. Approval requires every scene covered and every source dialogue ID assigned exactly once in its proper scene. Speaker association does not imply that an off-screen narrator appears in the picture.

A focused correction versions only its contract and preserves neighboring documents, approvals and media. The ordered sequence pins contract versions and needs explicit review after a changed pin or reorder. One planning-only whole-plan checkpoint atomically reviews the exact current contracts and sequence. Rejecting or revoking the sequence preserves individual contract review history while holding further eligibility.

Free preparation on an existing handoff appends only missing current-scene/dialogue coverage, preserving existing contracts, history, media and relative order. With nothing missing, it is a no-op and does not silently repin a changed sequence. Stale or removed-source contracts remain saved and held for explicit repair. Legacy adoption preserves existing shot IDs, order, direction and selected media; ambiguous dialogue or missing scene mappings require correction. Long scenes over the 900-second per-contract planning bound require splitting rather than truncation; the bound is not a renderer capability.

## Runtime and spending contracts

- The shared `director-storyboard-handoff-v1` archive stores bounded source history, independent shot histories and sequence history. Source bindings include the complete approved creative context and exact versions of all 17 departments. Any bound source/department change conservatively holds older contracts. Selective semantic shot-impact analysis is not claimed.
- `GET /api/projects/:id/storyboard-handoff` returns current context. `POST` supports `prepare`, focused `update`, `reorder`, explicitly acknowledged `review_sequence` and source `refresh`. All writes use the project version and approved current prerequisites. The specialized save also binds the latest approval identity under the database project lock.
- `POST /api/projects/:id/storyboard-handoff/apply-proposal` accepts an owned, completed saved call ID, validates its strict output and exact captured context, then saves through the same guarded path. Client-supplied output cannot replace saved model evidence.
- Whole approval uses the existing approval endpoint with artifact `storyboard_sequence`, its exact version and `ackPlanningOnly: true`. Direct contract-approval bypass is refused. Private review evidence uses a database-computed SHA-256 of the exact JSONB archive, sequence/project versions and acknowledgement; the locked RPC still compares the complete incoming archive. Private evidence is removed from public history responses.
- Typed contracts project their managed fields into existing shot records. Generic PATCH cannot overwrite these directions/order. Separate reference/media selection remains available, and prior assets/bindings survive handoff changes. Imports preserve creative history without copying approval or spending authority.
- New `plan_storyboard` / `storyboard_planning` uses `director-planning-v6`, its own reviewed schema/profile and a separately displayed model/cost allowance. Consent alone starts no call. Existing IDs and relative order, current approved documents and user decisions remain protected. An approved current sequence must be explicitly reopened before another paid planning request. Untyped legacy shots require free adoption before reserving money.
- Existing v3 writing, v4 department planning and v5 revision requests retain their saved contracts. Source changes, pause or model retirement hold new work while known submitted-request recovery/accounting remains available. Unknown submission keeps its financial hold and cannot trigger an automatic replacement.
- Full source facts, raw uploaded script, all department documents and existing contracts are preserved in the provider context. The measured large full-content fixture is 173,960 bytes within the unchanged 200,000-byte limit. Oversized inputs fail closed; facts are not truncated into a template.
- New media spending/dispatch requires a fresh approved handoff when an archive exists. Contract/sequence approvals cannot be used as generated-media targets. Planning approval establishes neither observed image/audio fidelity nor media acceptance, rights clearance, spending authorization or finished-film quality.
